## Версия 0.4 — доступ для компаний

Apollo предоставляет сервис компаниям-клиентам. Самостоятельной регистрации нет.

- Первый экран — логин и пароль, выданные Apollo или администратором компании.
- Основной аккаунт Apollo создаёт подтверждённый владелец сайта. Раздел «Компании Apollo» выдаёт отдельное рабочее пространство и учётную запись администратора компании.
- Администратор компании создаёт сотрудников с личными логинами, ролями и временными паролями. Пароль показывается только при выдаче и заменяется при первом входе.
- Сессии хранятся на сервере, cookie HttpOnly/Secure/SameSite=Lax. Пароли хешируются с индивидуальной солью; в исходном коде и localStorage их нет.
- Есть выход, смена собственного пароля, сброс сотруднику и администратору клиента, ограничение попыток входа. Отзыв членства сразу закрывает доступ к документам.
- Демонстрация производственной компании: запуск линии, заказ оборудования и актуализация документов. Изменения в демо не сохраняются.
- Промышленные шаблоны: ТЗ, производственный заказ, паспорт оборудования, закупка, контроль качества, корректирующие действия и регламенты.

### Первичная настройка

Владелец открывает серверный сайт, подтверждает свой доступ и нажимает «Настроить основной аккаунт Apollo». Логин и пароль он задаёт сам. После этого выдаёт доступ клиентам в разделе «Компании Apollo». Восстановление основного аккаунта также требует подтверждения владельца сайта.

Ключ `APOLLO_OWNER_EMAIL` задаётся секретом в среде хостинга; `APOLLO_GATEWAY_ORIGIN` разрешает POST формы входа с принадлежащего владельцу GitHub Pages. Учётные данные не передаются в URL.

## Что изменилось относительно 0.1

Основные записи хранятся в серверной базе Cloudflare D1, вложения — в R2. localStorage больше не является хранилищем корпоративных данных. Рабочие аккаунты используют логин и пароль. Подтверждение владельца Apollo для первоначальной настройки и восстановления обеспечивает Sign in with ChatGPT. Все запросы проверяют членство в пространстве и полномочия пользователя на сервере. Личные избранные страницы хранятся отдельно для каждого участника.

Сохранение использует номер ревизии. При конфликте чужая работа не перезаписывается: пользователю предлагается экспортировать свою копию и загрузить серверную. Новые данные проверяются серверной схемой.

## Доступ и совместная работа

Серверный сайт пока сохраняет прежний режим доступа хостинга — только владелец. Для внешних клиентов владелец должен отдельно разрешить доступ к экрану входа. При этом API всё равно требует действующую сессию Apollo Task и членство в нужной компании.

GitHub Pages показывает публичный экран входа и независимое демо. Форма отправляет логин и пароль непосредственно серверному сайту через HTTPS POST, а не GitHub API. В закрытом режиме хостинг может потребовать подтверждения владельца до обработки формы.

Ранее созданные компании, документы, задачи и карточки не удаляются. Основной аккаунт связывается с прежней идентичностью владельца, чтобы сохранить доступ к его данным.

## Запуск и размещение

Это серверное приложение Vinext/Cloudflare Workers. Простая раздача HTML или GitHub Pages не запускает базу данных, аккаунты и API.

```bash
corepack pnpm install --frozen-lockfile
npm run db:generate  # только после изменения схемы
npm run build
```

После первой сборки примените **только ещё не применённые** локальные миграции:

```bash
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_windy_legion.sql
npm run dev
```

Для просмотра собранного Worker: `npm start`. Для проверок: `npm run check`.

В размещении Sites базы D1/R2 объявлены в `.openai/hosting.json`; миграции применяются платформой при публикации. Этот файл идентифицирует существующую публикацию и не содержит секретов. Учётные данные, файлы `.env` и локальные базы в репозиторий не включаются.

GitHub Pages workflow публикует только страницу-переход `web/index.html` к серверному приложению. Интерфейс не использует GitHub как базу данных. Если Pages не разрешён политикой репозитория, используйте прямую ссылку на приложение выше.

## Пределы текущей реализации

Обновления общего пространства проверяются каждые пять секунд. Это совместная работа с автосохранением и контролем версий, без посимвольного объединения изменений (CRDT), общих курсоров и синхронного редактирования одного блока. Внешние ссылки сохраняют введённое человеком название/описание, без автоматического скачивания произвольных страниц. Нет платёжных тарифов, marketplace-плагинов Atlassian и enterprise SSO.

## Проверки

`npm run check` включает 17 тестов: модели и поиск, сохранение, изоляция компаний, права наблюдателя, приглашения, отзыв доступа, конфликты версий, персональные настройки, новые типы материалов и безопасная загрузка/скачивание вложений. Тестовый D1-адаптер исполняет реальные SQL-запросы в SQLite.

Браузерные сценарии: меню создания, доска/заметки/связи, база/записи/поля, шаблоны, кабинет, живой документ и адаптивная навигация. Управляемый локальный preview не выдаёт пользовательскую идентичность; серверные операции проверяются отдельно, а штатная авторизация работает на опубликованном сайте.

## Боковая панель — 0.4.1

Настройка через шестерёнку вверху панели или «Ещё → Настроить боковую панель». Можно скрыть и переставить пункты (перетаскиванием или стрелками), свернуть группы и папки, убрать пространства из личной навигации и закрепить до 12 быстрых ссылок. Скрытые модули доступны через «Ещё». Документы и разделы компании при этом не удаляются.

Панель сворачивается кнопкой слева в верхней строке или Ctrl/⌘ + [. Ширина меняется перетаскиванием границы; стрелки на выбранной границе тоже меняют ширину. Двойной щелчок возвращает стандартную ширину. На телефоне открывается выдвижная панель. Настройки сохраняются отдельно для пользователя и компании; они доступны и участникам с правом просмотра. При редактировании документов настройка панели не пересоздаёт редактор и сохраняет несохранённый текст.

Проверка: 35 тестов, включая изоляцию личных настроек, допустимые ссылки, порядок пунктов и ограничения ширины.
