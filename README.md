## Версия 0.3 — агентство

- Стартовая форма: имя, агентство и роль. Подтверждение через ChatGPT.
- Демо без входа на GitHub Pages: только вымышленные проекты, изменения живут в памяти вкладки. Пять подсказок можно закрыть и открыть снова.
- Клиентские проекты: бриф, папка материалов, стартовые задачи, ответственный, сроки, этап и архив.
- Внутренние согласования: назначенный проверяющий, решение, комментарий, история. После редактирования нужна новая проверка. Проект нельзя завершить с открытыми задачами и нерешёнными проверками.
- 10 подробных агентских шаблонов в дополнение к структурам команды, доскам и контент-плану.
- Новое пространство без вымышленных сотрудников и клиентов.

## Рабочие модули

- Личный кабинет: профиль, зона ответственности, задачи, страницы и черновики.
- Корпоративная wiki: разделы, страницы, папки, комментарии, версии и восстановление.
- Живые документы: автосохранение, загрузка обновлений с сервера и защита от конфликтов.
- Доски: заметки, цвета, перетаскивание, масштаб и связи.
- Базы данных: настраиваемые поля, записи, текст/число/дата/статус/сотрудник, поиск и CSV.
- Интеллектуальные ссылки: безопасные карточки внешних ресурсов.
- Задачи: доска/список, исполнители, сроки, приоритеты и ссылки на документы.
- Библиотека шаблонов для клиентских брифов, концепций, правок, встреч, сдачи и работы команды.
- Вложения к страницам (до 10 МБ), загрузка, скачивание и удаление.
- Рабочие пространства компаний, участники, одноразовые приглашения и роли owner/editor/viewer.
- Экспорт/импорт JSON, перенос данных первой версии.

## Что изменилось относительно 0.1

Основные записи хранятся в серверной базе Cloudflare D1, вложения — в R2. localStorage больше не является хранилищем корпоративных данных. Вход обеспечивает Sign in with ChatGPT. Все запросы проверяют членство в пространстве и полномочия пользователя на сервере. Личные избранные страницы хранятся отдельно для каждого участника.

Сохранение использует номер ревизии. При конфликте чужая работа не перезаписывается: пользователю предлагается экспортировать свою копию и загрузить серверную. Новые данные проверяются серверной схемой.

## Доступ и совместная работа

Публикация по умолчанию остаётся закрытой для владельца. До приглашения коллег предоставьте им доступ к опубликованному сайту в настройках его публикации. Ссылка приглашения в Apollo Task назначает роль в рабочем пространстве, **не меняет правила доступа хостинга**. Письма автоматически не отправляются: сервис выдаёт одноразовую ссылку на семь дней, при желании привязанную к почте.

Новые пространства содержат только карточку зарегистрированного владельца и инструкцию по процессу. Прежние пространства сохраняют своё содержимое. Карточки сотрудников и учётные записи участников разделены.

Публичный стартовый экран и демо доступны на GitHub Pages. Демо не обращается к API. Переход к реальному пространству ведёт на серверный сайт, где вход предварительно проверяет сама платформа.

## Запуск и размещение

Это серверное приложение Vinext/Cloudflare Workers. Простая раздача HTML или GitHub Pages не запускает базу данных, аккаунты и API.

```bash
corepack pnpm install --frozen-lockfile
npm run db:generate  # только после изменения схемы
npm run build
```

После первой сборки примените **только ещё не применённые** локальные миграции:

```bash
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_windy_legion.sql
npm run dev
```

Для просмотра собранного Worker: `npm start`. Для проверок: `npm run check`.

В размещении Sites базы D1/R2 объявлены в `.openai/hosting.json`; миграции применяются платформой при публикации. Этот файл идентифицирует существующую публикацию и не содержит секретов. Учётные данные, файлы `.env` и локальные базы в репозиторий не включаются.

GitHub Pages workflow публикует только страницу-переход `web/index.html` к серверному приложению. Интерфейс не использует GitHub как базу данных. Если Pages не разрешён политикой репозитория, используйте прямую ссылку на приложение выше.

## Пределы текущей реализации

Обновления общего пространства проверяются каждые пять секунд. Это совместная работа с автосохранением и контролем версий, без посимвольного объединения изменений (CRDT), общих курсоров и синхронного редактирования одного блока. Внешние ссылки сохраняют введённое человеком название/описание, без автоматического скачивания произвольных страниц. Нет платёжных тарифов, marketplace-плагинов Atlassian и enterprise SSO.

## Проверки

`npm run check` включает 17 тестов: модели и поиск, сохранение, изоляция компаний, права наблюдателя, приглашения, отзыв доступа, конфликты версий, персональные настройки, новые типы материалов и безопасная загрузка/скачивание вложений. Тестовый D1-адаптер исполняет реальные SQL-запросы в SQLite.

Браузерные сценарии: меню создания, доска/заметки/связи, база/записи/поля, шаблоны, кабинет, живой документ и адаптивная навигация. Управляемый локальный preview не выдаёт пользовательскую идентичность; серверные операции проверяются отдельно, а штатная авторизация работает на опубликованном сайте.
